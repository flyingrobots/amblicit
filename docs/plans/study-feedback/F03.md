## 2. Problem Description

Application build wraps CompilerError values in one ApplicationCompilationFailed Debug message. Tools cannot read each compiler kind and source location.

## 2b. Proposed Solution

Emit one structured compiler record per error. Preserve stable kinds and byte spans. Keep the existing ApplicationCompilationFailed summary without its Debug-vector payload.
Keep `line` as the 1-based JSONL request line when present. Add `sourceLocation` with path, 1-based source line, and 1-based Unicode-scalar column. Keep `span.start` and `span.end` as 0-based UTF-8 byte offsets.
Update the authoritative diagnostic and event schemas for build command/stage values. Preserve established check/project records, terminal error status, counts, and build exit behavior. Do not overload transport coordinates.

## 2c. Alternatives considered and rejected

Leave the limitation undocumented: authors cannot identify the contract boundary.
Combine unrelated fixes: a reviewer cannot verify one outcome independently.

## 2d. Acceptance Criteria

Validate every emitted build diagnostic and terminal record against its checked schema. Cover parser and compiler failures, multiple records, CRLF, EOF, and multibyte source. Assert command, stage, kind, path, coordinate units, status counts, and nonzero exit. No failed build publishes output. Preserve existing check/project schema witnesses.

## 2e. Test Plan

Golden: successful build records remain compatible. Edges: multiple errors, Unicode before the error, multiline source, and an empty span. Known failure modes: incorrect coordinates and partial output publication. Fuzz and stress: none; bounded CLI fixtures suffice.
