## 2. Problem Description

The JSON authoring API supports custom types and target adapters. The guide does not show a causal-cell executable recipe. Authors change the fixture generator instead.

## 2b. Proposed Solution

Provide an application-owned `edict.lawpack-authoring/v1` JSON definition through `edict.lawpack-build/v1`. Add a runnable how-to and public binary witness.
Use an application helper to derive all type limits, byte caps, budgets, and witness types from explicit inputs. This helper does not add compiler-level lawpack parameters.
For text, distinguish scalar maxima from physical UTF-8 byte caps. Show stock and 4 KiB byte-cap variants. Give the selected provider package identity and compatible schema/version. Verify both variants through actual authoring and application build.

## 2c. Alternatives considered and rejected

Compiler-level lawpack parameterization: the existing JSON API already supports owned definitions.
Change generator literals per application: this changes shared fixture authority and duplicates derived limits.
Treat scalar maxima as byte caps: non-ASCII input invalidates the size contract.

## 2d. Acceptance Criteria

Author and compile stock and larger-value variants through public JSONL operations. Do not modify the stock generator to vary application bounds. Check canonical identities and parameter consistency. State that compilation alone does not prove runtime execution.

## 2e. Test Plan

Golden: public authoring then application build. Edges: changed key/value maxima, UTF-8 expansion, output budget too small, and configuration/type disagreement. Known failure modes: unsynchronized limits. Fuzz and stress: none; two finite parameter sets suffice.
